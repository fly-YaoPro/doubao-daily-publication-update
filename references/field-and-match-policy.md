# 字段、匹配和互动数据口径

## 发布来源字段

机构每日执行文档的“5.3 机构发布视频”用于取得：发布平台、达人昵称、粉丝数、内容方向、发布日期、发布链接、发布文案、GID、抖音号、UID、合作码。自建达人没有独立机构执行文档，读取本周总执行文档“每日执行看版”中当天“日期-自建达人”区块内的同名发布表，字段口径相同。

每日任务和本周回溯都不依赖机构多维表或全量表。机构多维表通常次日上午更新，由机构登记筛查 Skill 单独考核；主页、稿件和发布证据取当周机构执行文档中的原始链接，客户表用于去重、补登、归属色块和审核状态回读；抖音客户表同时用于互动数据回读。豆尼不得修改机构执行文档或机构多维表。

## 公开数据能力

每日发布同步只允许调用抖音公开详情抓取。小红书已因平台自动化风控于 2026-08-27 停用：禁止打开作品页、解析短链、调用 MediaCrawler 小红书模式或更新小红书互动字段。

抖音内容详情可返回：

- `liked_count` → 赞；
- `comment_count` → 评；
- `collected_count` → 藏；
- `share_count` → 转发。

互动总和按四项数值相加。每个数必须带采集时间，页面返回隐藏值、空值、非数字或失败时不写。

当前适配器没有稳定落库抖音播放量。客户表的“阅读/播放”不得用点赞量、评论量或估算值代替；只有抖音页面确实返回并经过一次回读验证时才可写。小红书的阅读、赞、评、藏、转发和互动总和全部保持原值，不自动补零或清空。

抖音新发布内容的数据会继续增长。首次登记可写当前快照，24 小时后可重新采集并覆盖同一行的互动字段，同时保留采集日志。小红书不安排 24 小时互动复抓。

## 去重与写入

1. GID/作品 ID 完全一致，视为同一发布。
2. 规范化发布链接中的作品 ID 一致，视为同一发布。
3. 达人昵称 + 发布日期只作最后回退；唯一命中才可用。
4. 同一 GID/作品 ID（含抖音主页弹层 `modal_id/vid`）已经登记在更早日期时，视为历史重复：不得算作当天有效发布、不得重复补录，执行日志保留来源日期与客户表日期，但不再制造待人工核对项；这类记录也不得进入当天机构色块、互动数据、审核状态同步或指标检查。只有没有稳定作品 ID、仅规范化链接跨日冲突时才进入待核。
5. 同一达人跨机构并不矛盾。机构必须来自当前机构执行文档，不能根据达人历史机构猜测。
5. 写入前读取完整 current region、最新 revision 和目标行；写后按真实行号回读。
6. 末列机构归属标记不能省略，也不能把整行染色。12 家外部机构写既定色块；自建达人在末列写文字“自建”。
7. 主页、发布链接、稿件链接只向单元格写普通 `value=原始 URL`，由飞书自动生成标题。禁止传 `rich_text`、`linkUrl` 或自定义显示文本；否则会阻断飞书自动取标题，并把旧的错误点击目标固化下来。只有平台返回的无参数 URL 已实测可打开时才可去掉分享参数；不得根据作品 ID 自行拼接 `/explore/{id}` 等地址，无法验证时保留执行文档原始 URL。稿件链接以客户审核 Sheet 的原始稿件单元格为权威来源：`mention_type=22` 是 docx token，`mention_type=16` 是 Wiki node；解析后必须再用 `drive +inspect` 得到 canonical URL，解析不到标题、类型或 URL 时拒绝写入并进入待核。`docs +fetch` 能返回正文不等于页面可打开。
8. 新增客户表行必须根据实时表头识别胶囊字段，并显式继承可信历史模板行的下拉验证项、胶囊色和当前值；模板优先选择最近一个更早发布日期的完整数据行，禁止使用同批刚新增的上一行，避免格式错误级联。格式复制不等于数据验证复制。新增后统一为客户表标准 27px 行高；回读时，当前值不在下拉选项或选项与模板不一致，一律视为写入失败。
9. 发布登记后只对当天抖音有效记录抓取公开详情，写入赞、评、藏、转发与互动总和。小红书不得进入抓取器，未抓取不构成异常或待核；小红书发布补录、机构色块和审核状态同步仍继续。
10. 已填发布日期但缺发布链接的记录不是有效发布，只进入待核；任何单条异常都不得终止整批。
11. 当日执行文档缺粉丝量但主页、达人和作品证据完整时，优先从当前机构的多维执行表中补齐；必须同时满足同机构、同平台、同达人，并以同发布链接、唯一 ID 或同发布日期作唯一命中。机构多维表仍缺失时，才可从同平台客户审核 Sheet 的唯一同达人对应专项记录补齐。任何回退都禁止跨机构、跨项目或仅凭昵称猜值。
12. 飞书执行文档可能在某日章节中嵌套下一日或前一日的同步块。解析时必须按原文顺序扫描全部日期标题和发布表；每张发布表只继承其前面最近的日期标题。发布日期为空时不得使用当天日期兜底。无法找到最近日期标题的发布表进入待核，不计入发布与产能。
13. 每次每日更新必须逐日回溯本周周一至当天。历史记录若在执行文档存在而客户表缺失，则按当日同一写入规则补登；客户表已经存在时，按作品 ID/链接核对日期，并以执行文档所属机构重放末列机构色。客户表孤立记录只报告，不自动删除；日期或平台证据冲突时进入待核，不猜测修改。

## 客户审核状态同步

1. 抖音仅操作【工作任务-抖音视频审核】，小红书仅操作【工作任务-小红书视频审核】。
2. 发布表最终复查确认作品已存在后才允许同步；发布表仍缺失、链接冲突或来源不完整时不得先改审核状态。
3. 先读取执行文档“5.3 机构发布视频”的`内容方向`，把工作任务/办公任务与课程教学（兼容科普、科普号、科普专项）分开；内容方向写明“第 N 期”时，期数也属于强证据。再按平台 + 同专项 + 规范化达人昵称取得候选；昵称规范化忽略大小写、空格、emoji 和尾部机构备注。执行文档内容方向与客户审核表“对应项目”不一致时不得自动更新。
4. 必须读取客户审核表稿件单元格的 rich cell/mention 真实链接，再以 `drive +inspect` 解析 canonical URL 和文档标题，并用标题反查专项及期数。即使候选只剩一条，只要标题明确显示另一专项或另一课程期次，也不得自动命中。表格显示文本为空、只显示“打开稿件”，或发布来源没有直接携带稿件字段，都不能成为提前停止消歧的理由。专项和期数一致后，再排除已发布、暂停和取消的历史合作；只有一条当前合作时命中。仍有多条时按解析后的稿件标题/链接、主页和发布日期所在周期消歧；若上述证据没有唯一答案，只允许在候选中存在唯一最新周期时回退。同一审核行被两条当日发布同时命中，或最新周期仍有多条当前记录时，一律进入待核。发布文案/作品标题只能作为同达人候选内的辅助证据，不能跨达人建立关联；达人不同，即使文案完全一致，也禁止复制另一行的主页、稿件、审核状态或其它元数据。
5. 实时按表头查找“目前进度”；当前列字母虽均为 J，但不得写死。写入前确认该单元格下拉包含“已发布”，写入时保留下拉选项和高亮样式，写后回读值及数据验证。
6. 当前值已经是“已发布”时不重复写。发布表已存在但审核状态漏改时，后续任务仍应自愈补齐。

## APP 排除

内容方向包含 `APP`、`豆包app`、`手账skill`、`手账贴纸skill` 等明确 APP 标记时排除。“手账 Skill / 手账贴纸 Skill”已由业务确认属于 APP 端，不登记工作任务客户表、不进入 PC 产能。“专家模式”同样不属于工作任务客户发布表，直接排除。`spp端` 等高度疑似错别字进入人工复核；只有已有业务证据能确认其为 APP 时才排除，并在结论中列出。

## 已修复的失败模式

以下问题曾导致客户表补录或互动抓取不完整，执行时必须防回归：

1. **把两张客户表当成同一结构。** 抖音 E 列是“发布平台”，小红书 E 列是“内容形式”。不得因两表列名不同就误报“表头变化”，也不得复用固定列号写入。每次读取两张表的实时表头并分别建立字段语义映射。
2. **一条脏数据中断整批。** 执行文档中缺发布链接的记录只能进入待核，不能阻断其他有效发布的登记与互动抓取。
3. **抖音互动抓取没有和发布登记闭环。** 必须先补录、再按当日抖音有效发布全量重扫、抓取、写入、逐行回读；禁止只处理本次新增的抖音行。
4. **误启动小红书自动化访问。** 小红书短链不得跟随跳转，作品页不得打开，抓取器不得以 `xhs` 平台运行。小红书只同步机构已提供的发布事实；历史互动数据保持原样。
5. **把“明确为 0”和“字段缺失”混为一谈。** 平台明确返回空计数时可按 0 写入；字段不存在、隐藏或解析失败时保持空白并进入待核，禁止补 0 掩盖失败。
6. **新增行格式级联污染或链接标题被人为固化。** 不得把同批刚写入的上一行当作格式模板；应从更早发布日期的可信历史行复制普通格式。链接列只能写普通 URL value，绝不写 rich-text 显示文本；随后显式恢复 27px 行高和各胶囊字段的数据验证。
7. **把 docx token 写成 Wiki 地址。** 已确认 `mention_type=22` 是 docx token，旧解析器曾错误拼成 `/wiki/<token>`，导致客户表里出现“页面不存在”。`mention_type=16` 才按 Wiki node 解析。两者都必须经过 `drive +inspect` 得到 canonical URL 后再写；写入后验证点击目标，而不只是验证单元格字符串。
8. **把同一作品跨日重复计入。** 只比较 GID/链接、不比较客户表发布日期，会把前一天已发布的内容重复算进当天。命中稳定作品 ID 且客户表日期更早时，直接标记历史重复，从当天发布、机构分布、互动、审核同步和产能中同时排除；只有没有稳定作品 ID 的链接跨日不一致才列为待核冲突。
9. **把嵌套同步块继承成外层日期，或把分节编号当日期。** 只读取最外层日期章节、在发布日期为空时默认运行当天，或把“5.3 机构发布视频”识别成 5 月 3 日，都会造成整批错日。必须按标题层级和原文顺序处理：只有真实日期标题切换日期，5.1/5.2/5.3 永远只是业务分节；每张表归属于前面最近的真实日期标题。
10. **把机构多维表备注当作公开作品链接。** 当天互动抓取只使用当周执行文档中的真实发布链接；机构多维表里的发布列可能尚未更新或含“最快今天给到视频”等备注，禁止覆盖权威作品链接。
11. **重复合作先按发布周筛选。** 历史审核行可能保留旧周期。必须先找尚未发布/暂停/取消的当前合作，再用稿件、主页、周期消歧；不能让历史已发布记录把当前待发布记录挡住。
12. **抖音抓取器登录失效后逐条报错。** 出现账号封禁、登录态失效或没有生成结果时，只报告一条抖音平台级系统异常，避免把同一故障伪装成多个达人问题。小红书不进入此链路。
13. **本周总执行文档漏机构却按零发布处理。** 每次先用活跃机构清单核对入口覆盖；缺入口属于来源失败，不是该机构零发布。
14. **机构平台胶囊填错导致写错客户表。** 发布链接域名是平台强证据：`douyin.com/v.douyin.com` 路由抖音，`xiaohongshu.com/xhslink.cn` 路由小红书；原胶囊与链接冲突时自动纠正路由并记录原值，不让脏字段阻断其他记录。
15. **课程教学或昵称大小写导致审核行假缺失。** 课程教学兼容旧称科普/科普号/科普专项；达人昵称匹配必须忽略大小写、空格、emoji 和尾部机构备注，例如“要要要AI”与“要要要ai”应视为同一达人。
16. **忽略执行文档内容方向导致串专项、串期次。** “工作任务”和“课程教学”必须先分池；“课程教学第一期/第二期”等期数必须与审核表稿件链接解析出的文档标题交叉验证。专项或期数明确冲突时禁止用“唯一当前行”兜底。

卡片只对业务人员报告“互动抓取：抖音已完成/需复核/无当日发布；小红书已停用”，不展示抓取条数；抖音逐条互动值和失败原因留在客户表与执行日志中。
